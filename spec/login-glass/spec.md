# Feature Specification: 登录页液态玻璃全原生重构（login-glass）

**Created**: 2026-11-05  
**Status**: Draft  
**Input**: User description: "重构一下登录页面，只保留输入手机号和获取验证码登录，设计美观一点，可以融入液态玻璃效果"

## Overview

将当前基于 WebView 内嵌官方登录页的登录界面，重构为**全原生液态玻璃风格登录页**：仅保留手机号输入 + 短信验证码登录一种方式，底层直连 DeepSeek 短信登录 API（需先经嗅探抓包逆向获取真实端点）。重构后登录页视觉与应用内既有液态玻璃设计语言（液态玻璃气泡、白底玻璃加号按钮）保持一致。原 WebView 登录与嗅探调试工具保留为隐藏入口，作为逆向取证工具与故障回退路径。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 原生手机号验证码登录（Priority: P1）

用户打开登录页，看到全原生液态玻璃表单（品牌标识、手机号输入框、验证码输入框 + 获取验证码按钮、登录按钮）。输入手机号 → 点击"获取验证码"收到短信 → 输入验证码 → 点击"登录" → 校验通过后自动写入登录凭证并进入聊天页。

**Why this priority**: 这是本次重构的核心目标——用原生 UI 替代 WebView，视觉与可靠性双提升；没有它整个特性不成立。

**Independent Test**: 可独立测试：输入真实手机号完成一次完整短信登录流程；即使后续故事未实现，也已交付可用的登录能力。

**Acceptance Scenarios**:

1. **Given** 未登录状态，**When** 进入登录页，**Then** 展示原生玻璃表单（无 WebView、无微信扫码、无 Apple 登录、无密码登录链接）
2. **Given** 合法手机号已输入，**When** 点击"获取验证码"，**Then** 按钮进入 60 秒倒计时状态，短信实际送达
3. **Given** 验证码已输入，**When** 点击"登录"，**Then** 凭证写入成功并自动跳转聊天页，会话列表可正常加载
4. **Given** 验证码错误或过期，**When** 点击"登录"，**Then** 展示友好错误提示，停留在登录页可重试
5. **Given** 原生登录 API 调用失败（网络/风控/接口变更），**When** 用户需要登录，**Then** 可通过隐藏入口进入 WebView 登录回退流程完成登录

---

### User Story 2 - 液态玻璃视觉设计（Priority: P1）

登录页整体采用液态玻璃设计语言：磨砂玻璃卡片承载表单、品牌蓝登录按钮、背景与聊天页一致的柔和渐变、玻璃质感状态提示（加载中/成功/失败）。视觉品质对标应用内已验收的液态玻璃气泡效果。

**Why this priority**: 用户明确要求"设计美观一点，融入液态玻璃效果"，与登录功能同为核心诉求。

**Independent Test**: 可独立测试：截图对比视觉验收标准（玻璃卡片、模糊背景、按钮质感、暗色适配），无需完成真实登录即可验证大部分视觉效果。

**Acceptance Scenarios**:

1. **Given** 登录页展示，**When** 观察/截图，**Then** 表单卡片呈现磨砂玻璃质感（半透明、背景模糊、细边框高光、柔和阴影），与聊天页玻璃组件风格统一
2. **Given** 系统切换深色模式，**When** 再次进入登录页，**Then** 玻璃效果与配色正确适配深色模式，无对比度问题
3. **Given** 小屏/大屏设备，**When** 布局渲染，**Then** 表单居中、安全区（状态栏/键盘）正确避让，键盘弹出时输入框不被遮挡

---

### User Story 3 - 登录 API 逆向取证与隐藏调试入口（Priority: P2）

保留原 WebView 登录 + 嗅探工具，但收进隐藏入口（如标题栏长按呼出），不占用常规界面。逆向取证：利用嗅探工具记录一次真实短信登录的完整 API 请求（发送验证码端点、登录端点、请求头、请求体、响应结构），作为原生实现的依据。

**Why this priority**: 原生登录的实现依赖真实端点数据，取证是 US1 的前置条件；隐藏化是"只保留手机号验证码"的用户要求。取证完成后嗅探入口继续保留供未来接口变更时排查。

**Independent Test**: 可独立测试：长按标题栏呼出嗅探开关与 WebView 登录入口；完成一次抓包并导出日志；不触发隐藏入口时界面完全无调试元素。

**Acceptance Scenarios**:

1. **Given** 登录页，**When** 长按标题区域，**Then** 弹出隐藏菜单（嗅探模式开关 + WebView 登录入口 + 日志查看）
2. **Given** 无任何长按/隐藏操作，**When** 常规使用登录页，**Then** 界面无任何调试元素外露
3. **Given** 嗅探模式开启且经 WebView 完成一次短信登录，**When** 查看嗅探日志，**Then** 可完整复制发送验证码与登录两条 API 请求记录

---

### Edge Cases

- 手机号未输入或格式不合法时点击"获取验证码"：按钮不发起请求，输入框给出校验提示
- 验证码发送频率超限（服务端限流）：展示服务端返回的限流提示文案，按钮保持可重试状态
- 登录请求进行中重复点击"登录"：按钮置为加载态防重复提交
- 原生登录端点被 PoW/风控拦截导致失败：给出"可使用备用网页登录"的引导提示，用户可走隐藏 WebView 入口完成登录
- 已登录状态下再次进入登录页（凭证仍有效）：直接自动进入聊天页，不展示登录表单
- 嗅探日志导出失败（剪贴板异常）：降级提示重试，不崩溃

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供全原生登录表单，仅包含：手机号输入（+86 区号展示）、验证码输入、获取验证码按钮（60 秒倒计时）、登录按钮；不出现微信扫码、Apple 登录、密码登录等任何其他登录方式
- **FR-002**: 系统 MUST 通过逆向取证获得的真实端点直连 DeepSeek 短信登录 API，完成发送验证码与提交登录两步流程，成功后复用现有 TokenStore 写入凭证并跳转聊天页
- **FR-003**: 系统 MUST 在原生登录失败时提供 WebView 登录回退能力（隐藏入口可达），保证登录功能永不中断
- **FR-004**: 登录页 MUST 采用液态玻璃视觉（磨砂玻璃卡片、背景模糊、品牌蓝主按钮、柔和阴影），并正确适配深色模式与安全区/键盘避让
- **FR-005**: 系统 MUST 保留嗅探模式开关、API 记录面板与 WebView 登录入口，但收进隐藏交互（长按呼出），常规界面零调试元素
- **FR-006**: 系统 MUST 对手机号格式（11 位数字）与验证码格式（按取证结果约定的位数）做输入校验，非法输入给出提示且不发起请求
- **FR-007**: 获取验证码与登录按钮 MUST 具备防重复提交（倒计时/加载态），网络错误与服务端错误 MUST 以友好文案提示

### Key Entities *(include if feature involves data)*

- **登录凭证（userToken）**: 登录成功后获得的用户令牌，写入现有 TokenStore，后续 API 请求以 Bearer 方式携带；实体不变，仅获取方式改变
- **短信登录请求（两步）**: 发送验证码请求（手机号）与登录请求（手机号+验证码），请求头/体结构以嗅探取证结果为准
- **嗅探日志**: WebView 登录过程中捕获的 API 请求记录，用于取证与排查，保留现有导出能力

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户使用真实手机号可在 1 分钟内完成"输入手机号 → 收码 → 输码 → 登录成功进入聊天页"全流程
- **SC-002**: 登录页视觉验收通过：玻璃卡片、按钮质感、深色模式、安全区适配全部符合设计基线，与既有液态玻璃组件风格统一（截图对比）
- **SC-003**: 常规登录界面 100% 无调试元素外露（无嗅探开关、无 API 记录、无微信/Apple/密码登录入口）
- **SC-004**: 原生登录路径失败时，用户经隐藏入口走 WebView 登录仍可 100% 完成登录（回退保障）
- **SC-005**: 重构后既有功能零回归：登录后的会话列表、聊天、TTS、抽屉等功能不受影响

## Assumptions

- DeepSeek 网页端短信登录 API 可被逆向并从应用直连调用；若存在 PoW 挑战，可复用现有 PowSolver 基础设施；若存在不可绕过的风控，则回退 WebView 方案（US1 场景 5 保障）
- 取证阶段需要用户配合接收一次真实短信验证码（应用数据已清空，用户本就需要重新登录）
- 登录成功后的凭证格式与现有 TokenStore 完全一致（同为 userToken），下游代码零改动
- "只保留手机号+验证码登录"指界面呈现层面；WebView 登录作为回退能力保留但默认不可见

## Open Questions

- 原生登录端点是否需要 PoW 挑战或特殊请求头（如 x-ds-pow-response）？——以嗅探取证结果为准，实现阶段解决
- 验证码有效期与位数、限流策略等服务端行为——以取证与实测为准，UI 层做成可配置容错
